## Незмінні правила (privacy-контракт; порушення = зупинка і перепланування)

1. Web залишається повністю робочим local-only на кожному коміті; будь-яка синхронізація — лише за окремою явною згодою; її відсутність нічого не ламає.
2. Медичні значення (симптоми, оцінки, цикл, нотатки, підсумки, **назви груп/станів**) ніколи не потрапляють в URL, логи, аналітику, тексти помилок, Telegram-повідомлення. Логи — тільки білим списком з §11 плану.
3. Згоди незалежні (`health_sync` ≠ `telegram_reminders` ≠ `cycle_sync`); legacy-поля (`remOn` тощо) — не згода.
4. Сервер не аналізує вміст записів: E2E-модель §7 не ослаблюється «тимчасово для налагодження». Жодних plaintext-медичних колонок у БД, жодного серверного парсингу payload.
5. Тексти бота і нагадувань — лише статичний exact allowlist зі специфікації; без інтерполяції; нагадування «сліпе».
6. `BOT_TOKEN` ніколи не потрапляє в env/конфіг api-процесу (лише bot і reminder_worker; api — `TELEGRAM_BOT_ID` + публічний Ed25519-ключ).

## Порядок виконання

0. **Підготовка.** Репозиторій зараз без комітів: зроби initial commit незміненого поточного стану (щоб кожна фаза була окремим відстежуваним комітом). Створи `docs/plans/backend-bot-plan-progress.md` — чекліст фаз і DoD-пунктів; онови його наприкінці кожної фази.
1. **Фаза 0 — Фундамент** (за §12): docker-compose (PostgreSQL 16), `.env.example` (з `TELEGRAM_BOT_ID`, без значень секретів), alembic + міграція 0001 (схеми `diary`/`reminders`, три ролі, GRANT-матриця §6.3), пін залежностей (fastapi/uvicorn/pydantic явно, import-linter ≥ 2.0), CI (ruff + mypy strict + pytest + lint-imports + gitleaks), каркас шарів §5.1 з контрактами §5.2. Сюди ж — дрібні узгодження контракту, якщо ще не зроблені окремо: прибрати `"states"` з `ExportState.sub` (звірити з `apps/web/src/lib/types.ts` `Sub`), тест на це.
2. **СТОП: Gate D.** Після Фази 0 зупинись і сформуй пакет для дизайн-рев'ю (перелік рішень §7/§6.4/§4.3/§10 + чернетки consent copy і текстів для користувачки + кандидат політики quiet hours). Продовжуй Фази 1–4 ЛИШЕ якщо в «Параметрах запуску» явно зазначено статус Gate D. Якщо не зазначено — завершуй сесію звітом.
3. **Фази 1 → 2 → 3 → 4 → 5** — строго послідовно за §12 плану. DoD кожної фази — це acceptance-критерії: фаза не завершена, поки КОЖЕН DoD-пункт не закритий тестом або артефактом. Не починай наступну фазу з незакритими DoD.

## Дисципліна якості

- **TDD**: спершу тест (який падає), потім реалізація. Для конкурентних сценаріїв §9 (409 під локом, гонка erasure vs push, компакшн/410, монотонність ревізій) — інтеграційні тести на реальній PostgreSQL (testcontainers-python; потрібен запущений Docker — перевір на старті, якщо його немає, зупинись і повідом).
- **Наскрізні gates після кожної фази**: `pnpm test`, `pnpm build`, `pnpm e2e` (web); `uv run pytest && uv run ruff check .` в `apps/api` і `apps/bot`; `lint-imports` без порушень. Червоне = фаза не завершена; чужі тести не «лагодити» ослабленням.
- Роутери тонкі; вся бізнес-логіка в `app/services/*`; ORM/сесії не вище `infra/db/repositories`; жодного SQL у роутерах. Контракти import-linter — механічна перевірка цього; не переписуй їх під код, переписуй код під них.
- Один комміт (або кілька атомарних) на фазу; повідомлення з префіксом фази (`phase-0: …`). Секрети не комітити ніколи (gitleaks у CI + перевір руками `.env` у `.gitignore`).

## Межі змін

- МОЖНА: `apps/api/**`, `apps/bot/**` (лише якщо фаза цього вимагає; `/start`-поведінка і тест-allowlist не змінюються), новий `apps/web/src/sync/**` (Фаза 2: крипто-модуль, серіалізація, журнали видалень, гігієна initData — як ACL §4.5, НЕ чіпаючи reducer/domain web), кореневі інфра-файли (compose, CI), `docs/plans/backend-bot-plan-progress.md`.
- НЕ МОЖНА: `docs/plans/future-telegram-reminders.md`, `docs/review-gates.md`, `docs/prototype/**`; доменна логіка web (`apps/web/src/state/`, `apps/web/src/lib/` — крім точок інтеграції, явно передбачених планом); UI-affordances синку/нагадувань до працюючого наскрізного шляху (чесний unavailable-state лишається); `README.md` — оновлюй лише секцію запуску інфраструктури, без оголошення функцій доступними.
